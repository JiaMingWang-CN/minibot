# minibot 里程碑 1（单 bot 闭环）实现计划

> **For agentic workers:** Implement this plan task-by-task, in order. Each task's requirements include the Global Constraints below; each task's Interfaces block tells you the names and types neighboring tasks use. Steps use checkbox (`- [x]`) syntax for tracking — tick each one as it is done.

**Goal：** 做出可用的 minibot 桌面端里程碑 1：首次初始化、主 bot、三种模型格式、文件/命令工具、审批、多线程、记忆。

**Architecture：** `packages/core` 是不依赖 Electron UI 的内核（模型适配器、agent 循环、工具、审批、记忆、SQLite 存储），由一个 `Kernel` 门面对外。`Kernel` 之上是一层本机 HTTP + WebSocket 服务（只绑 `127.0.0.1`，令牌 + `Host`/`Origin` 校验）。`apps/desktop` 的 Electron 主进程启动内核和服务，渲染进程（纯 TS + DOM，无框架）只通过这套接口通信。

**Tech Stack：** TypeScript 5.9.3、Electron 45.2.3（Node 24.22.2）、`node:sqlite`、`node:test`、`ws` 8.22.1、`@vscode/ripgrep` 1.18.0。

**Spec：** `docs/specs/2026-11-07-minibot-core-design.md`（依据 `requirements.md`）。本计划只覆盖里程碑 1；spec §8.2 的委托与群聊（里程碑 2）另写计划。

## Global Constraints

- 运行时以 Electron 45.2.3 内置的 **Node 24.22.2** 为准，不得使用 Node 24.22 之后才有的 API。本地测试在 Node 26 上用类型剥离直接跑 `.ts`。
- TypeScript 5.9.3，`strict: true`、`erasableSyntaxOnly: true`（不用 enum、namespace、参数属性）；相对导入写 `.ts` 后缀，构建时用 `rewriteRelativeImportExtensions: true`。
- 依赖只允许：`electron@45.2.3`、`ws@8.22.1`、`@vscode/ripgrep@1.18.0`、`typescript@5.9.3`、`@types/node@24.19.2`、`@types/ws`。其余一律不加；模型 API 用 `fetch` 加自写的 SSE 解析，不引 SDK。
- 测试框架用 `node:test` + `node:assert/strict`。测试文件放在 `packages/core/test/*.test.ts`，运行：`node --test packages/core/test/`。
- 平台：Windows + Linux。win32 下路径比较不区分大小写。
- 数据根目录 `~/.minibot`。内核所有函数都接收 `dataRoot` 参数，测试用临时目录，不碰真实 `~/.minibot`。
- `config.json`、`bot.json`、`secrets.bin`、记忆 `.md` 一律经 `atomicWriteFile` 写入。
- API Key 不明文落盘；所有日志、工具结果、模型生成文本在落库/推送/发送之前都经 `SecretSet.redact`；占位符字面量为 `[REDACTED_API_KEY]`。
- 界面文字只有简体中文，全部放在语言包 `apps/desktop/src/renderer/i18n/zh-CN.ts` 里。
- 用户全局规则：使用 Electron、`ws`、`@vscode/ripgrep` 的 API 之前，先用 Context7 或在 scratchpad 里写探针脚本核实。
- 本项目不是 git 仓库：没有提交步骤。

## Review Focus

1. 应用在一轮进行中被强退：重启后线程历史里有悬空的 `tool_use`。期望：启动时自动补 `cancelled` 的工具结果，该线程能继续对话（Task 4）。
2. Windows 上用 CRLF 换行的文件：模型照着 `read_file` 的输出写 `edit_file` 的 `old_string`（只含 `\n`）。期望：替换成功且保留 CRLF（Task 12）。
3. 工作目录路径含中文和空格，命令输出中文。期望：命令在该目录执行，输出不乱码（Task 13）。
4. 供应商在流式输出中途断开或返回 5xx。期望：本轮以一条提示结束，历史仍合法，下一条消息能正常发送（Task 17）。
5. 模型把记忆写成嵌套路径或非法主题名（如 `memory/C++/Rust.md`）。期望：拒绝并说明规则，不在记忆目录里建子目录（Task 12）。
