# 扩展第 5 期：Skill 实现计划

> **For agentic workers:** Implement this plan task-by-task, in order. Each task's requirements include the Global Constraints below; each task's Interfaces block tells you the names and types neighboring tasks use. The plan gives approach and constraints only — you write the tests and the code. Steps use checkbox (`- [ ]`) syntax for tracking — tick each one as it is done.

**Goal:** 支持 agentskills.io 规范的 skill：单独添加或来自插件；按 bot 启用；名称和描述常驻系统提示；模型用 `load_skill` 按需读取；用户在输入框用 `/` 点名。

**Architecture:** `packages/core/src/skills/` 负责发现与校验（单独添加的在 `~/.minibot/skills/`，插件的在 `plugins/<name>/skills/`）、按 bot 计算可用 skill、`load_skill` 内置工具。每轮快照时把 skill 摘要一并取好，交给 `buildSystemPrompt`。点名作为一种新的用户消息块存进历史。

**Tech Stack:** TypeScript、YAML frontmatter 解析库（Task 1 选型）、React 19。

**Spec:** `docs/specs/2026-11-12-extensions-design.md` §5.5（另见 §6）。依赖第 1–4 期计划已完成（插件里的 `skills/` 在第 4 期已登记）。

## Global Constraints

- `name`：1–64 位小写字母、数字、连字符，不以连字符开头或结尾，不含 `--`，且与目录名一致；`description`：1–1024 字符。不合规的 skill 不加载，界面显示原因。
- `allowed-tools` 字段读取后忽略，不改变任何审批。
- `load_skill` 是内置工具，不弹审批；读取范围严格限制在该 skill 目录内（复用 `path-guard` 的真实路径解析，防 `..` 和符号链接逃逸）；单文件大小上限同 `read_file`（`MAX_READ_BYTES` 10 MB）。
- 重名时单独添加的优先，界面提示冲突。
- 新加的 skill 默认只对主 bot 启用。
- 工具列表和 skill 摘要每轮开头取一次快照。
- 界面文案进 `apps/renderer/src/i18n.ts`；视觉遵守 `.claude/CLAUDE.md`。新依赖锁定精确版本，使用前核实。
- 测试：`node --test "packages/core/test/*.test.ts"`；`npm run build --workspace @minibot/core`；`npm run build --workspace @minibot/renderer`；`npm run build --workspace @minibot/mobile`；`npm run lint`。

## Review Focus

- `SKILL.md` 带 BOM、CRLF 换行或 frontmatter 后没有正文 → 正常解析，正文为空也能加载（Task 1）。
- skill 目录里有指向目录外的符号链接（或 Windows 目录联接）→ `load_skill` 拒绝读取（Task 2）。
- 用户点名的 skill 在发送前被停用或删除 → 发送时提示该 skill 不可用，消息不发出，输入保留（Task 4）。
- 一个 bot 启用了很多 skill → 摘要过长时仍能发送；摘要总长超过上限时截断并说明（Task 2）。
- 历史里有点名块的线程在旧版手机端打开 → 显示为普通文字，不崩溃（Task 3）。

### Task 1: skill 发现、校验与存储

**Files:**
- Create: `packages/core/src/skills/skill.ts`、`packages/core/src/skills/store.ts`
- Modify: `packages/core/src/paths.ts`、`packages/core/src/plugins/registry.ts`、`packages/core/package.json`
- Test: `packages/core/test/skills.test.ts`、`packages/core/test/fixtures/skills/`

**Interfaces:**
- Produces:
  - `interface SkillInfo { id: string; name: string; description: string; dir: string; origin: { kind: 'user' } | { kind: 'plugin'; pluginName: string }; shadowed: boolean }`（`id`：单独添加的为 `user:<name>`，插件的为 `plugin:<pluginName>:<name>`）
  - `interface SkillProblem { dir: string; reason: string }`
  - `readSkill(dir: string, origin: SkillInfo['origin']): Promise<SkillInfo>`（不合规抛错，`message` 为原因）
  - `SkillService.list(): Promise<{ skills: SkillInfo[]; problems: SkillProblem[] }>`
  - `SkillService.add(srcDir: string): Promise<SkillInfo>`、`SkillService.remove(id: string): Promise<void>`
  - `SkillService.body(id: string): Promise<{ dir: string; body: string }>`
  - `DataPaths.skillsDir`（`<root>/skills`）

**思路:**
- frontmatter 用成熟的 YAML 解析库（锁定精确版本），只取 `name`、`description`，其他字段忽略；先去掉 BOM，按 `---` 行切分，兼容 CRLF。
- `list`：扫描 `skills/` 下每个子目录和每个已启用插件的 `skillDirs`；合规的进 `skills`，不合规的进 `problems`；插件 skill 与单独添加的同名时，插件那个 `shadowed: true`（不可用、界面提示冲突）。
- `add`：校验源目录 → 目标 `skills/<name>/` 已存在则拒绝 `已有同名 skill：<name>` → 复制整个目录（不跟随符号链接，遇到链接跳过并计入提示）→ `enableForMainBot('skills', id)`。
- `remove`：只允许 `user:` 开头的 id；删除目录，`removeFromAllBots('skills', id)`。
- 第 4 期插件确认页里 skill 的“下一版本支持”提示在本 task 去掉，改为显示校验结果。

**约束:**
- 原因文案：`缺少 SKILL.md`；`缺少 frontmatter`；`name 不合规：<规则>`；`name 必须与目录名一致`；`description 必须是 1–1024 个字符`。

**验收:**
- `合规`：fixtures `pdf-tools/SKILL.md` → `name`、`description` 正确。
- `BOM 与 CRLF`：同内容加 BOM、CRLF → 解析结果相同。
- `目录名不一致`：目录 `a`、`name: b` → 原因 `name 必须与目录名一致`。
- `description 超长`：1025 字符 → 对应原因。
- `allowed-tools 忽略`：带 `allowed-tools: Bash(*)` → 正常加载，`SkillInfo` 无相关字段。
- `同名遮蔽`：单独添加与插件各有 `pdf-tools` → 单独添加的可用，插件的 `shadowed: true`。
- `添加默认主 bot`：`add` 后只有主 bot 的 `extensions.skills` 含其 id。
- `删除插件 skill 被拒`：`remove('plugin:x:y')` → 失败。

### Task 2: 常驻摘要与 `load_skill`

**Files:**
- Create: `packages/core/src/skills/load-skill.ts`
- Modify: `packages/core/src/tools/catalog.ts`、`packages/core/src/tools/registry.ts`、`packages/core/src/approval/policy.ts`、`packages/core/src/agent/prompt.ts`、`packages/core/src/agent/loop.ts`、`packages/core/src/kernel.ts`
- Test: `packages/core/test/load-skill.test.ts`、`packages/core/test/loop.test.ts`

**Interfaces:**
- Consumes: `SkillService`（Task 1）、`TurnToolset`（第 1 期）
- Produces:
  - `TurnToolset` 新增 `skills: SkillInfo[]`（本轮该 bot 可用的 skill）
  - `SystemPromptArgs` 新增 `skills: { name: string; description: string }[]`
  - 内置工具 `load_skill`，参数 `{ name: string; path?: string }`
  - `formatSkillBody(info: SkillInfo, body: string): string`（`load_skill` 与点名共用）

**思路:**
- 快照时按 `bot.extensions.skills` 和插件启用情况（bot 的 `extensions.plugins` 含插件名时，其未被遮蔽、且 id 不在 `pluginExclusions` 里的 skill 也可用）求出本轮 skill；为空时不加 `load_skill` 工具、不加摘要段。
- 系统提示在记忆段之后（不论记忆开关）追加：`可用的 skill：` 加每行 `- <name>：<description>`，再加一行约定 `任务和某个 skill 相关时，先调用 load_skill 读取说明再动手。`
- `load_skill` 不带 `path`：返回 `formatSkillBody`（第一行 `skill 目录：<dir 绝对路径>`，空行，`SKILL.md` 正文）。带 `path`：在该 skill 目录内解析真实路径，越界拒绝；读取文本文件，二进制拒绝；超过 10 MB 拒绝。
- `load_skill` 在审批判断里视为直接放行（不经过 `decide` 的路径分类）。

**约束:**
- 摘要段总长上限 8000 字符；超出时按 skill 顺序截断，末尾加一行 `（还有 {n} 个 skill 未列出，可用 load_skill 按名字读取）`，未列出的 skill 仍可被 `load_skill` 读取。
- 错误文案：`没有这个 skill：<name>`；`路径超出 skill 目录`；`不是文本文件`；`文件太大（上限 10 MB）`。

**验收:**
- `摘要`：bot 启用 `pdf-tools` → 系统提示含 `- pdf-tools：<description>` 和约定行，工具列表含 `load_skill`。
- `无 skill`：bot 未启用任何 skill → 系统提示不含 `可用的 skill`，工具列表不含 `load_skill`。
- `读正文`：`load_skill({name:'pdf-tools'})` → 第一行是目录路径，随后是正文；不发审批请求（`ask` 档下也一样）。
- `读引用文件`：`path: 'references/a.md'` → 返回其内容。
- `越界`：`path: '../other/SKILL.md'` → `路径超出 skill 目录`。
- `链接越界`：skill 目录内一个指向外部文件的符号链接 → 同上（不支持建链接的环境跳过此测试）。
- `摘要截断`：启用 200 个描述 100 字的 skill → 摘要段 ≤ 8000 字符，末尾有“还有 n 个”行；`load_skill` 读未列出的那个成功。
- `未启用不可读`：读一个存在但该 bot 未启用的 skill → `没有这个 skill：<name>`。

- [ ] **Step 2:** 实现。
- [ ] **Step 3:** 测试 PASS，全量无回归。
- [ ] **Step 4:** 提交。

### Task 3: 点名块：消息结构与发送

**Files:**
- Modify: `packages/core/src/model/types.ts`、`packages/core/src/model/chat-completions.ts`、`packages/core/src/model/responses.ts`、`packages/core/src/model/anthropic.ts`、`packages/core/src/agent/compaction.ts`、`packages/core/src/kernel.ts`、`packages/core/src/server/dispatch.ts`、`packages/core/src/remote/gateway.ts`
- Test: `packages/core/test/adapter-chat.test.ts`、`packages/core/test/adapter-responses.test.ts`、`packages/core/test/adapter-anthropic.test.ts`、`packages/core/test/kernel.test.ts`

**Interfaces:**
- Consumes: `SkillService.body`、`formatSkillBody`（Task 1、2）
- Produces:
  - `Block` 新增 `{ type: 'skill'; name: string; text: string }`（`text` 为 `formatSkillBody` 的结果）
  - 发送消息的输入新增可选 `skills: string[]`（skill 名）

**思路:**
- 内核收到带 `skills` 的消息：逐个确认该 bot 本轮可用，取全文，生成 `skill` 块放在用户文字块之前，一起存进这条用户消息。
- 三个适配器把 `skill` 块当作一段用户文本发送，文本为 `已加载 skill：<name>\n\n<text>`。
- 压缩时 `skill` 块按普通文本计入与摘要。
- 推给界面和手机的消息里照常包含 `skill` 块。

**约束:**
- 点名的 skill 不可用 → 整条消息拒绝，`KernelError('invalid', 'skill 不可用：<name>')`，不落库。

**验收:**
- `存进历史`：带 `skills: ['pdf-tools']` 发送 → 用户消息首块为 `skill` 块，其后为文字块。
- `下一轮仍可见`：下一轮 `callModel` 收到的历史仍含该段文本。
- `三种适配器`：含 `skill` 块的历史在 chat_completions、responses、anthropic_messages 的请求体里都成为用户文本，内容以 `已加载 skill：pdf-tools` 开头。
- `不可用被拒`：点名一个未启用的 skill → `invalid`，线程消息数不变。

### Task 4: Skill 界面：扩展页、bot 开关、`/` 菜单与折叠显示

**Files:**

- Modify: `packages/core/src/server/dispatch.ts`、`apps/renderer/src/api.ts`、`apps/renderer/src/settings/ExtensionsPage.tsx`、`apps/renderer/src/panel/SettingsPage.tsx`、`apps/renderer/src/main/Composer.tsx`、`apps/renderer/src/main/Transcript.tsx`、`apps/renderer/src/i18n.ts`、`apps/mobile/src/screens/`（显示 `skill` 块的组件）
- Test: `packages/core/test/dispatch.test.ts`

**Interfaces:**
- Consumes: Task 1–3
- Produces: 接口 `GET /api/skills`（`skills` 与 `problems`）、`POST /api/skills`（`{ dir }`）、`DELETE /api/skills/:id`、`GET /api/bots/:id/skills`（该 bot 可用的 skill，供 `/` 菜单）

**思路:**
- “扩展”页增加“Skill”栏：列表（名称、描述、来源、冲突提示）、问题列表（目录与原因）、“添加”（选择目录）、删除（仅单独添加的）。
- bot 面板“扩展”一节增加 skill 开关列表（单独添加的写 `extensions.skills`）；插件行展开后除 MCP server 外也列出它的 skill，每项一个开关（写 `pluginExclusions`）。
- 输入框：内容以 `/` 开头且光标在第一个词内时，弹出 `SkillMenu`（复用 `Menu` / `Popover`），按输入过滤名称，上下键选择、回车或点击选中；选中后把 `/xxx` 换成一个可删除的标签。可以点名多个。发送时带上 `skills`；若接口返回 `skill 不可用`，提示并保留输入。
- 消息列表里 `skill` 块折叠显示为一行 `已加载 skill：<name>`，点击展开全文。手机端同样折叠显示。

**约束:**
- 文案（逐字）：栏名 `Skill`；`添加 Skill`；冲突提示 `与单独添加的同名 skill 冲突，未启用`；折叠行 `已加载 skill：{name}`；菜单为空时 `没有可用的 skill`。

**验收:**
- `添加接口`：`POST /api/skills` 指向 fixtures 合规目录 → 201；不合规目录 → 400 并带原因。
- 手动：在临时 `MINIBOT_HOME` 下添加一个 skill → bot 面板可见开关 → 输入框打 `/` 弹出菜单并能过滤 → 选中后发送，消息里显示折叠行、可展开；模型回答体现 skill 内容。截图菜单、折叠与展开状态、扩展页的 Skill 栏。
- 手机网页层构建通过，含 `skill` 块的消息显示为折叠行。
