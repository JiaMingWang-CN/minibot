# 扩展第 3 期：MCP 实现计划

> **For agentic workers:** Implement this plan task-by-task, in order. Each task's requirements include the Global Constraints below; each task's Interfaces block tells you the names and types neighboring tasks use. The plan gives approach and constraints only — you write the tests and the code. Steps use checkbox (`- [ ]`) syntax for tracking — tick each one as it is done.

**Goal:** 用户能在设置里添加 MCP server（stdio / Streamable HTTP，可 OAuth 登录），按 bot 启用，server 提供的 tools 作为外部工具交给模型，调用走审批。

**Architecture:** `packages/core/src/mcp/` 里：配置（存 `extensions.json`，敏感值存 `secrets.bin`）、`McpManager`（每个 server 全局一个连接，管理状态、工具缓存、重启、超时）、OAuth（本机回调 + 密钥库存 token）、`McpToolProvider`（把缓存的工具按 bot 转成第 1 期的 `ExternalTool`）。协议、版本兼容和 OAuth 流程交给官方 SDK `@modelcontextprotocol/client`。

**Tech Stack:** `@modelcontextprotocol/client`（写 spec 时 2.4.0，实现时锁定精确版本）、Node 24、Electron `shell.openExternal`、React 19。

**Spec:** `docs/specs/2026-11-12-extensions-design.md` §5.3（另见 §2 反目标、§5.7、§6）。依赖第 1、2 期计划已完成（`ToolCatalog`、`extensions.json`）。

## Global Constraints

- 不手写 MCP 协议；客户端、传输、版本协商、OAuth 一律用 SDK。使用任何 SDK API 之前，用 Context7 或探针脚本核实，核实结果记在 Task 1 的探针说明里。
- 必须同时能连 2026-07-28 版（无握手、无状态）和更早的、以 `initialize` 握手的 server。
- 每个 server 全局一个实例；工作目录取配置的 `cwd`，单独添加的默认 `~/.minibot`。
- stdio 子进程只拿到配置声明的环境变量，加上最小系统变量：Windows `SystemRoot`、`SystemDrive`、`PATH`、`PATHEXT`、`COMSPEC`、`TEMP`、`TMP`、`USERPROFILE`、`APPDATA`、`LOCALAPPDATA`、`HOMEDRIVE`、`HOMEPATH`、`PROGRAMDATA`；Linux `PATH`、`HOME`、`USER`、`LANG`、`TMPDIR`。
- 关闭或重启 stdio server 必须结束整个进程树（复用 `tools/process.ts` 的 `killTree`）。
- 单次调用超时默认 60 秒；stdio 崩溃自动重启最多 3 次。
- 工具名：`<server 短名>__<工具名>`，必须匹配 `^[a-zA-Z0-9_-]{1,64}$`。
- 敏感值（标记为 secret 的环境变量、请求头、OAuth token 与客户端注册信息）只存 `secrets.bin`，键名 `mcp:<serverId>:env:<NAME>`、`mcp:<serverId>:header:<Name>`、`mcp:<serverId>:oauth`；加载时登记进脱敏集合。没有密钥库时，需要敏感值的 server 不能保存，提示 `当前系统没有可用的密钥库，无法保存这个 MCP server 的密钥`。
- 不信任 server 自报的任何工具标注。
- 只接 tools；不实现 resources、prompts、sampling、elicitation。
- 界面文案进 `apps/renderer/src/i18n.ts`；视觉遵守 `.claude/CLAUDE.md`。
- 测试：`node --test "packages/core/test/*.test.ts"`；`npm run build --workspace @minibot/core`；`npm run build --workspace @minibot/renderer`；`npm run build --workspace @minibot/desktop`；`npm run lint`。

## Review Focus

- server 启动后不响应（stdio 卡住）→ 连接在 30 秒内判为失败，内核启动和其他 server 不受影响（Task 2）。
- 调用中途用户点“停止”→ 取消请求，本轮以已取消结束；stdio server 继续可用（Task 2）。
- 同一个 server 的两个工具规范化后同名，或两个 server 短名相同 → 名字带短哈希区分，不互相覆盖（Task 3）。
- OAuth 授权页被用户关掉、从不回调 → 5 分钟后回调监听关闭，server 状态回到“需要登录”，不留端口（Task 4）。
- 用户从网上粘贴的 JSON 带有本系统不支持的字段（如 `disabled`、`autoApprove`）→ 忽略并提示，不报错（Task 5）。

**Files:**

**Interfaces:**
- Produces:
  - `type McpTransportConfig = { type: 'stdio'; command: string; args: string[]; cwd: string | null; env: Record<string, McpValue> } | { type: 'http'; url: string; headers: Record<string, McpValue>; auth: 'none' | 'oauth' }`
  - `type McpValue = { secret: false; value: string } | { secret: true }`（secret 值本身只在密钥库）
  - `interface McpServerConfig { id: string; name: string; shortName: string; transport: McpTransportConfig; timeoutMs: number; origin: { kind: 'user' } | { kind: 'plugin'; pluginId: string } }`
  - `ExtensionsFile` 新增 `mcpServers: McpServerConfig[]`
  - `parseMcpJson(text: string): { servers: McpServerDraft[]; ignored: string[] }`，`McpServerDraft` 为未分配 id、值未分 secret 的草稿

**思路:**
- 第一步写探针脚本（放 scratchpad，不进仓库）：用 SDK 连接一个旧版 stdio 测试 server 和一个 2026-07-28 版的测试 server，列工具、调用工具、取消调用，记下实际用到的类名和方法。测试用 server 用 SDK 自己的 server 端实现写成 fixtures（两个版本各一个，外加一个“启动后不响应”和一个“调用后崩溃”的）。
- `shortName`：从 `name` 生成，只保留 `[a-zA-Z0-9_-]`，其余字符换成 `_`，截到 20 个字符；为空时用 `mcp`。
- `parseMcpJson` 接受 `{ "mcpServers": { <name>: {...} } }`：有 `command` 为 stdio（`args`、`env`、`cwd`）；有 `url` 为 http（`headers`）；`type` 为 `sse` 的标为不支持并放进 `ignored`。其他未知字段名收进 `ignored`。
- 环境变量和请求头的值，名字里含 `KEY`、`TOKEN`、`SECRET`、`PASSWORD`、`AUTH`（不区分大小写）的，草稿里默认标记为 secret，用户在确认对话框里可以改。

**约束:**
- `timeoutMs` 默认 `60000`，允许 1000–600000。
- `name` 去重：同名时拒绝保存，提示 `已有同名的 MCP server`。

**验收:**
- `解析 stdio`：`{"mcpServers":{"fs":{"command":"npx","args":["-y","x"],"env":{"API_KEY":"k"}}}}` → 一个 stdio 草稿，`API_KEY` 默认 secret。
- `解析 http`：`{"mcpServers":{"n":{"url":"https://a.example/mcp","headers":{"Authorization":"Bearer t"}}}}` → http 草稿，`Authorization` 默认 secret。
- `忽略字段`：带 `disabled`、`autoApprove` → `ignored` 含这两个字段名，草稿正常生成。
- `sse 不支持`：`type: 'sse'` → 不生成草稿，`ignored` 含该 server 名。
- `shortName`：`name` 为 `我的 Notion!` → `shortName` 为 `___Notion_`。
- `存取`：保存一个 server 后重读 `extensions.json` 一致，secret 值不在文件里。

### Task 2: McpManager：连接、状态、工具缓存、调用

**Files:**
- Create: `packages/core/src/mcp/manager.ts`、`packages/core/src/mcp/stdio-env.ts`
- Modify: `packages/core/src/kernel.ts`、`packages/core/src/events.ts`
- Test: `packages/core/test/mcp-manager.test.ts`

**Interfaces:**
- Consumes: `McpServerConfig`（Task 1）、`SecretStore`、`killTree`
- Produces:
  - `type McpStatus = 'connecting' | 'connected' | 'failed' | 'needs_login' | 'stopped'`
  - `interface McpServerState { id: string; status: McpStatus; error: string | null; tools: McpToolInfo[] }`
  - `interface McpToolInfo { name: string; description: string; inputSchema: Record<string, unknown> }`
  - `class McpManager { start(): Promise<void>; stop(): Promise<void>; states(): McpServerState[]; connect(id: string): Promise<void>; disconnect(id: string): Promise<void>; refreshTools(id: string): Promise<void>; call(id: string, tool: string, input: Record<string, unknown>, signal: AbortSignal): Promise<McpCallResult> }`
  - `interface McpCallResult { content: McpContent[]; isError: boolean }`（`McpContent` 为 SDK 返回内容的本地类型：text / image / 其他）
  - `KernelEvent` 新增 `{ type: 'mcp_status'; serverId: string; status: McpStatus; error: string | null }`

**思路:**
- `start()`：对“至少一个 bot 的 `extensions.mcpServers` 含它”的 server 并发连接，不等待全部完成就返回；内核 `init()` 末尾调用，`close()` 时 `stop()`。
- stdio 子进程环境：由 `stdio-env.ts` 按 Global Constraints 组装，secret 值从密钥库取；`cwd` 不存在时状态 `failed`，错误 `工作目录不存在：<path>`。
- 连接成功后列工具并缓存；收到工具变更通知或 `refreshTools` 时重新拉取。缓存变化只影响之后的快照（第 1 期快照规则）。
- 连接超过 30 秒没完成 → `failed`，错误 `连接超时`。
- stdio 进程意外退出：自动重连，连续失败计数达到 3 次后停在 `failed`，错误 `已重启 3 次仍失败，请手动重连`；手动 `connect` 清零计数。
- `call`：用 SDK 的请求超时（`timeoutMs`）和取消；外部 `signal` 中止时取消该请求并抛 `AbortedError`。server 未连接时直接返回错误结果 `MCP server 未连接：<name>`。
- 每次状态变化发 `mcp_status` 事件；`error` 文本经 `secrets.redact`。

**约束:**
- 一个 server 的失败、卡死、崩溃不得影响其他 server 和对话主流程（全部异步、各自 try/catch）。
- 删除或停用最后一个使用它的 bot 后，断开该 server。

**验收:**
- `连旧版与新版`：分别用两个 fixtures server → 状态 `connected`，`tools` 含其工具。
- `不响应`：启动后不说话的 server → 30 秒后 `failed`（测试里用注入的较短超时）；同时另一个正常 server 已 `connected`。
- `崩溃重启`：每次调用后退出的 server → 自动重连，第 3 次失败后停在 `failed` 并带上述错误文案；手动 `connect` 后恢复。
- `调用超时`：工具睡 2 秒、`timeoutMs` 1000 → 返回错误结果，server 仍 `connected`。
- `取消`：调用中止 signal → 抛 `AbortedError`，之后再调用正常。
- `环境隔离`：内核进程设 `SECRET_X=1`，server 回显自身环境 → 不含 `SECRET_X`，含配置声明的变量。
- `停止清进程树`：`stop()` 后 stdio server 及其子进程都已退出（用 fixtures 里会再起一个子进程的 server 验证）。

- [ ] **Step 1:** 写上述测试；运行 `node --test packages/core/test/mcp-manager.test.ts`，预期 FAIL。
- [ ] **Step 2:** 实现，并在内核里创建、启动、关闭 `McpManager`。
- [ ] **Step 3:** 测试 PASS，全量无回归。
- [ ] **Step 4:** 提交。

### Task 3: McpToolProvider：工具命名、结果映射、审批接入

**Files:**
- Create: `packages/core/src/mcp/tools.ts`
- Modify: `packages/core/src/kernel.ts`
- Test: `packages/core/test/mcp-tools.test.ts`

**Interfaces:**
- Consumes: `McpManager`（Task 2）、`ExternalTool` / `ExternalToolProvider` / `ToolCatalog`（第 1 期）
- Produces: `class McpToolProvider implements ExternalToolProvider`、`toolNameFor(shortName: string, tool: string, taken: Set<string>): string`

**思路:**
- `toolsFor(bot)`：遍历 `bot.extensions.mcpServers` 里状态为 `connected` 的 server，按 server 配置顺序、工具原顺序生成 `ExternalTool`，来源 `{ kind: 'mcp', serverId, serverName: name, toolName: 原名 }`。
- `toolNameFor`：`<shortName>__<tool>`，不合法字符换成 `_`；超过 64 字符或已被占用时，截短并在末尾加 `_` 和原始 `serverId + 工具原名` 的 sha256 前 6 位十六进制。
- `spec.description` 用 server 给的描述，前面加 `[MCP · <server 名>] `；`parameters` 用 `inputSchema`，缺失时 `{ type: 'object', properties: {} }`。
- 结果映射：text 按顺序用空行拼接；image 一律转成文字占位（见约束）；resource / resource_link 转成 `[资源：<uri>]`；其他类型 `[不支持的内容类型：<type>]`。`isError: true` → 工具错误。
- `summarize`：`调用 MCP 工具：<server 名> / <工具原名>`；`preview`：参数 JSON（缩进 2）。

**约束:**
- 本期 image 内容统一转成文字 `[图片：<mimeType>，暂不支持传给模型]`。spec 写的“模型支持图片时作为附件”需要给 `tool_result` 加图片支持，牵涉三种 API 适配器，本计划不做，记为已知差距。

**验收:**
- `命名`：shortName `notion`、工具 `search` → `notion__search`。
- `非法字符`：工具 `get.page` → `notion__get_page`。
- `冲突`：两个工具规范化后同名 → 第二个带 `_` 加 6 位十六进制后缀，二者都可调用且各自路由到正确的原始工具。
- `超长`：shortName 20 字符 + 60 字符工具名 → 名字长度 ≤ 64 且匹配正则。
- `只列已连接`：bot 启用了两个 server，一个 `failed` → 快照里只有已连接那个的工具。
- `未启用不出现`：server 已连接但 bot 未启用 → 快照里没有它的工具。
- `结果映射`：返回 `[text "a", image png, text "b"]` → `a\n\n[图片：image/png，暂不支持传给模型]\n\nb`。
- `审批走 mcp`：`edits` 档调用 → 发审批请求，`serverName` 为 server 名。

- [ ] **Step 2:** 实现并在内核注册 provider。

### Task 4: OAuth

**Files:**
- Create: `packages/core/src/mcp/oauth.ts`
- Modify: `packages/core/src/mcp/manager.ts`、`packages/core/src/kernel.ts`、`apps/desktop/src/main.cts`
- Test: `packages/core/test/mcp-oauth.test.ts`

**Interfaces:**
- Consumes: `McpManager`（Task 2）、`SecretStore`
- Produces:
  - `OpenOptions.openExternal?: (url: string) => Promise<void>`（桌面端传入封装好的 `shell.openExternal`）
  - `McpManager.login(id: string): Promise<void>`、`McpManager.logout(id: string): Promise<void>`

**思路:**
- 按 SDK 提供的 OAuth 客户端接口实现一个“客户端信息与 token 存储”：读写 `mcp:<serverId>:oauth`（JSON：客户端注册信息、token、code verifier 等 SDK 需要持久化的内容）。
- `login`：在 `127.0.0.1` 的随机端口起一个只处理 `GET /callback` 的一次性 HTTP 服务；把 `http://127.0.0.1:<port>/callback` 作为回调地址交给 SDK；SDK 给出授权地址后调用 `openExternal`；收到回调（校验 `state`）后把 code 交给 SDK 完成换取，回一个简单的“授权完成，可以关闭此页面”的 HTML，然后关闭监听并重连该 server。
- 连接时 SDK 报需要授权 → 状态 `needs_login`；token 刷新失败同样回到 `needs_login`。
- `logout`：删除密钥库里该 server 的 oauth 条目，断开，状态 `needs_login`。
- 桌面主进程：`openExternal` 只允许 `https:` 和 `http:`（沿用 `main.cts` 现有检查）。

**约束:**
- 回调监听只绑 `127.0.0.1`，5 分钟内没收到回调就关闭，状态回 `needs_login`，错误 `授权超时`。
- 回调里 `state` 不匹配 → 返回 400，不关闭监听（等真正的回调）。
- token 永不写入日志、事件、`extensions.json`。

**验收:**
- 用 fixtures 里一个需要 OAuth 的 http 测试 server（SDK 提供的授权服务端示例，或自写的最小授权服务器）：`login` → `openExternal` 收到授权地址；测试代码模拟浏览器访问该地址并跟随到回调 → 状态变 `connected`，可以调用工具。
- `刷新`：把 access token 设成过期 → 下一次调用前自动刷新成功。
- `刷新失败`：授权服务器拒绝 refresh → 状态 `needs_login`。
- `超时`：`login` 后不回调，超时（测试注入较短时长）→ 端口已关闭，状态 `needs_login`，错误 `授权超时`。
- `state 不匹配`：回调带错误 `state` → 400，随后正确回调仍能完成。
- `logout`：之后密钥库中无该条目，状态 `needs_login`。

- [ ] **Step 1:** 写上述测试；运行 `node --test packages/core/test/mcp-oauth.test.ts`，预期 FAIL。
- [ ] **Step 2:** 实现，桌面主进程传入 `openExternal`。
- [ ] **Step 3:** 测试 PASS，全量无回归；`npm run build --workspace @minibot/desktop` 通过。
- [ ] **Step 4:** 提交。

### Task 5: MCP 接口与界面

**Files:**
- Create: `apps/renderer/src/settings/ExtensionsPage.tsx`、`apps/renderer/src/settings/McpServerDialog.tsx`
- Modify: `packages/core/src/kernel.ts`、`packages/core/src/server/dispatch.ts`、`apps/renderer/src/api.ts`、`apps/renderer/src/settings/SettingsDialog.tsx`、`apps/renderer/src/panel/SettingsPage.tsx`、`apps/renderer/src/i18n.ts`
- Test: `packages/core/test/dispatch.test.ts`

**Interfaces:**
- Consumes: Task 1–4 的全部 Produces；`Kernel.enableForMainBot` / `removeFromAllBots`（第 1 期）
- Produces:
  - `GET /api/mcp/servers` → `{ servers: (McpServerConfig & McpServerState)[] }`
  - `POST /api/mcp/servers`（body：草稿 + secret 值）→ 新 server；`PATCH /api/mcp/servers/:id`；`DELETE /api/mcp/servers/:id`
  - `POST /api/mcp/parse`（body `{ text }`）→ `parseMcpJson` 的结果
  - `POST /api/mcp/servers/:id/connect`、`/refresh`、`/login`、`/logout`
  - `SettingsPageId` 新增 `'extensions'`

**思路:**
- 新增 server：保存 → 写配置与密钥 → `enableForMainBot('mcpServers', id)` → 连接。删除：断开 → 删密钥 → `removeFromAllBots` → 删配置。
- 设置弹窗新增“扩展”页，本期只有“MCP”一栏：列表（名称、类型、状态点和错误、工具数）、每行的连接 / 刷新 / 登录 / 删除操作；“添加”按钮打开对话框，可手填或“从 JSON 粘贴”。
- 对话框保存 stdio server 前，单独一步确认：完整显示将要运行的命令行（命令 + 参数，按 shell 习惯加引号显示）和工作目录，按钮“确认并启动”。
- 状态通过 `mcp_status` 事件实时刷新。
- bot 面板“扩展”一节增加 MCP server 列表，逐项开关（写 `extensions.mcpServers`）。

**约束:**
- 文案（逐字）：页名 `扩展`；栏名 `MCP`；状态 `连接中` / `已连接` / `连接失败` / `需要登录` / `已停止`；确认标题 `将在这台电脑上运行以下命令`；确认按钮 `确认并启动`；粘贴入口 `从 JSON 粘贴`；忽略字段提示 `以下字段不支持，已忽略：{fields}`。
- 接口返回的 server 不含任何 secret 值，只含 `{ secret: true }` 标记。

**验收:**
- `添加后默认只给主 bot`：两个 bot，`POST` 一个 server → 只有主 bot 的 `mcpServers` 含它。
- `删除清理`：删除后密钥库无 `mcp:<id>:` 开头的键，所有 bot 不再引用它。
